# 扩展测试数据说明

在基础演示数据上追加更多账号和课程，方便通过页面测试。不会清空已有数据，也不会改变原来11个当前教学班的人数。以下人数和状态指刚追加完成时，后续操作会改变它们。

## 1. 导入方法

先按[README](../README.md)建表、导入基础演示数据，通过`config.local.php`或`CR_DB_*`环境变量配置数据库连接。在项目根目录的PowerShell窗口执行，`$phpExe`使用README中设置的实际PHP路径。若此前启用了`CR_DEMO_MODE=1`，先停止网站并移除该变量，再以数据库模式启动。

```powershell
& $phpExe .\database\import_more_demo.php --demo-more
```

如果还没有基础演示数据，先运行：

```powershell
& $phpExe .\database\import_demo.php --demo
& $phpExe .\database\import_more_demo.php --demo-more
```

脚本追加12个学生、4个教师、9门课程、10个当前教学班和2个历史班。另有22个停用占位账号，用来准备不同班级人数；这些账号不能登录。

脚本通过TEST109课程的专用描述识别已导入状态，重复执行会跳过，不会重置已编辑资料、选课或成绩，也不会补回手动删除的账号。遇到账号或课程编号冲突时，本次追加全部回滚，不覆盖原记录。只在演示或测试库运行；已关闭的学期无法首次追加，请使用新的演示库。

新增可登录账号的密码均为`Demo@2026`。数据仅在数据库模式下可见；如配置了`CR_CATALOG_FILE`，需要更新快照或取消该配置后重启服务，避免旧快照缺少新增课程。

## 5. 可以直接操作的例子

各例默认使用刚导入的数据，且当前学期处于开放期。先完成查询、登录与拒绝操作，再做选课、认领、成绩修改；关课单独使用初始数据。以下例子不是可以不恢复数据就连续执行的固定流程。

student08、student09的初始方案如下，备选顺序从左到右：

| 学生 | 首选 | 备选 | 方案保存时间 |
| --- | --- | --- | --- |
| student08 | TEST101-01、TEST102-01、TEST104-01、TEST105-01 | TEST106-01、TEST103-01 | 2026-10-01 09:00:00 |
| student09 | TEST101-01、TEST103-01、TEST104-01、TEST106-01 | TEST102-01、TEST105-01 | 2026-10-01 09:01:00 |

重新正式提交会刷新方案保存时间，可能改变补位先后；保存草稿不改变这个顺序。

### 正常选课

使用`student04`，首选填写：

```text
TEST101-01、TEST102-01、TEST104-01、TEST106-01
```

备选填写：

```text
TEST105-01、TEST109-01
```

刚导入且处于开放期时可提交。成功后TEST101-01、TEST102-01、TEST104-01、TEST106-01的人数分别变为4、10、3、4，两个备选不占名额。

先修失败建议先用`student05`提交同一方案，确认被拒绝且人数不变，再用`student04`完成正常提交。若先完成正常提交，TEST102-01已满，再换账号可能同时触发满额提示，不能只据此判断先修检查。

student04退掉TEST102-01后，该班回到9人，其他三个首选仍然占座。确认整份删除可释放该学生的全部当前占座，但这不等于恢复整个数据库；再次测试关课时应恢复初始数据。

### 教师认领

使用`teacher04`认领TEST109-01，应提示无资格。教务员`admin01`在“任教与计费”授予课程TEST109的资格后，该教师可重试。

认领成功后，先由teacher04取消本人主动认领，再换teacher02认领该班并取消。若teacher04仍占有任教关系，teacher02应被拒绝，不能据此判断teacher02资格不足。资格使用课程编号TEST109，认领使用教学班编号TEST109-01。

取消任教不会自动撤销已授予的资格；再次验证teacher04无资格的场景时，应先由教务员撤销对应资格，或恢复初始数据。

### 成绩维护

使用`teacher03`打开历史软件测试班`TEST103-HIST`，可查看student04的A、student05的I、student06的空成绩和student07的B。修改后让对应学生登录查询。

教师只能维护本人任教班级的成绩；另用其他教师访问该班成绩录入入口，应拒绝。学生成绩页按登录身份查询，不能通过修改参数读取他人成绩。检查完成后将上述四条成绩恢复为原值；清空使用页面的清空操作，不输入文字“空”。

### 关课与补位

在独立测试库恢复初始数据，不认领TEST105-01，不修改student08和student09的方案，也不保留前面student04的新增选课。将当前学期截止设为当前北京时间之前、但晚于选课开始时间的合法时刻，再由教务员关闭选课。

TEST105-01因无教师停开；第一轮补位后，TEST104-01仍只有2人，因此停开。student08补入TEST106-01，其另一个备选TEST103-01已满，最终保留3门课；student09补入TEST102-01，最终保留4门课。

| 核对对象 | 初始数据下的关课预期 |
| --- | --- |
| student08最终课表 | TEST101-01、TEST102-01、TEST106-01 |
| student09最终课表 | TEST101-01、TEST103-01、TEST106-01、TEST102-01 |
| TEST104-01、TEST105-01 | 均停开，有效人数均为0 |
| TEST102-01、TEST106-01 | 有效人数分别为10、4 |
| 再次关闭 | 显示已有结果，不重复补位或新增计费快照 |

如果student04仍选有TEST104-01，该班人数已达到3人，上表中的停开与补位结果就不再适用。

关课会影响本学期全部课程，请只在可丢弃的测试库执行。原有11个班也会按相同规则处理。脚本不会自动更改截止时间；当前样例截止为北京时间2026年11月1日17:00。


## 6. 数据变化与恢复

重复导入不是重置方法。`import_demo.php`遇到已有基础业务数据时拒绝导入；`import_more_demo.php`识别扩展数据后直接跳过。`schema.sql`只创建缺失的表，也不会恢复账号、人数、成绩或学期状态。

| 操作 | 会改变的数据 | 再次测试前的处理 |
| --- | --- | --- |
| 正式选课、退课、整份删除 | 方案、有效占座、人数及草稿 | 简单演示可退回原选择；需要相同初始状态时恢复完整备份 |
| 教师认领、取消认领 | 教师安排与主动认领记录 | 由认领教师取消；授予的资格由教务员另行撤销 |
| 成绩保存、更正、清空 | 对应历史选课的成绩 | 按第5节原值恢复，或恢复备份 |
| 人员修改、停用、重置密码或删除 | 账号、资料、资料版本及会话有效性 | 使用专用测试账号；恢复后退出并重新登录 |
| 关闭选课 | 学期状态、教学班状态、方案、占座、补位结果和计费快照 | 恢复关课前完整备份，或使用新的独立测试实例 |

需要重复演示时，可按以下顺序准备：

1. 在独立MySQL测试实例中运行`schema.sql`，依次导入基础和扩展数据。建表脚本固定使用`course_registration`库；仅在MySQL客户端选择另一个库名，不能改变脚本的目标库。
2. 核对当前教学班共21个，其中新增10个；新增班人数应与第4节一致。人数按`enrollments.status='active'`统计，包含停用占位账号的有效选课，不能只统计可登录学生。
3. 在业务操作前保存整个测试库的结构和数据备份。将这一份作为初始备份，不混用已经选课或关课后的备份。
4. 下一轮演示前停止PHP服务，将初始备份恢复到干净的独立测试实例，并确认应用连接的是该实例。重新启动服务、退出旧登录会话后再登录；如使用JSON目录快照，还需保持快照与数据一致。
5. 没有备份时，使用新的独立测试实例重新建表并依次导入。不要只将已关闭学期的状态改回开放，也不要只清空某张业务表，避免关课结果与占座记录不一致。

样例开放时间为北京时间2026年9月21日08:00至11月1日17:00，包含起止时刻。超过该日期演示时，应在测试库同步调整开放学期的起止时间，保持开始时间早于截止时间。仓库中的截止延期脚本固定延长到2026年11月1日，不是随运行日期自动延期；调整时间不会撤销已完成的关课。

以上账号、课程和人数依据[扩展导入脚本](import_more_demo.php)，基础数据依据[基础导入脚本](import_demo.php)。自动检查见[`db_more_demo.php`](../tests/db_more_demo.php)，由统一测试入口在临时实例中执行；其检查内容包含重复导入保留修改和关课后再次导入不重开学期。
