# 课程注册系统

软件工程课程项目，使用 PHP 和 MySQL 实现学生选课、教师授课及教务管理。采用普通 PHP 页面与业务函数组织代码，适合本地演示和课程答辩。

## 主要功能

| 角色 | 功能 |
| --- | --- |
| 学生 | 课程查询、4个首选和2个备选、保存草稿、退课、查看课表和成绩 |
| 教师 | 按资格认领教学班、查看教师课表、搜索/导出名单、批量维护与统计成绩、确认提交和查询修改记录 |
| 教务员 | 人员资料与账号管理、任教资格、截止后关课和备选补位、模拟计费 |

计费只模拟发送，不产生费用；外部课程目录以本地JSON快照模拟。选课页面自动更新名额并提示首选满额，正在填写的方案会保留，保存时再次检查名额。

## 快速启动

需要 PHP 8.0+、PDO MySQL 扩展和 MySQL 8.0.16+。首次运行先在MySQL中执行[建表脚本](database/schema.sql)，然后配置连接并导入演示数据。配置与启动步骤如下：

1. 将根目录的 `config.example.php` 复制为 `config.local.php`，填写本机 MySQL 用户名、密码和端口。
2. 启动 MySQL 服务，在项目根目录打开 PowerShell。
3. 将下方PHP路径改为本机路径，再运行连接检查和网站。

```powershell
$phpExe = 'D:\phpstudy_pro\Extensions\php\php8.0.2nts\php.exe'
& $phpExe .\tests\db_connection.php

# 仅首次使用空数据库时执行；已有数据时跳过。
& $phpExe .\database\import_demo.php --demo

& $phpExe -S localhost:8000 -t .\Page
```

已有数据库升级时，还需在MySQL客户端执行[`database/add_teacher_grade_tools.sql`](database/add_teacher_grade_tools.sql)，新增成绩确认和修改记录表；脚本可重复执行，不改动已有成绩。

浏览器访问 <http://localhost:8000/>，关闭服务按 `Ctrl+C`。网站目录必须为 `Page`；本机配置位于网站目录外，已被Git忽略。不要上传数据库密码或数据备份。

### 配置与运行模式

配置优先级：`CR_DEMO_MODE=1` 强制演示 → 已设置 `CR_DB_USER` 时整组采用 `CR_DB_*` 环境变量 → 根目录 `config.local.php` → 无数据库用户时使用演示模式。

| 模式 | 数据保存 | 功能范围 |
| --- | --- | --- |
| 数据库模式 | 保存到MySQL，可由不同账号共享 | 完整的学生、教师、教务业务 |
| 会话演示模式 | 内置样例与当前浏览器会话，退出后不保留修改 | 课程查询、学生选课和教师认领演示；不替代数据库验收 |

无需MySQL即可体验演示模式：

```powershell
$env:CR_DEMO_MODE = '1'
& $phpExe -S localhost:8000 -t .\Page
```

恢复数据库模式时，先停止PHP，再执行 `Remove-Item Env:CR_DEMO_MODE -ErrorAction SilentlyContinue` 并重新启动。环境变量仅对当前终端及子进程生效。项目不自动读取 `.env`。数据库密码与网页登录密码不同。

## 演示账号与数据

| 角色 | 用户名 | 初始密码 |

| 学生 | `student01` | `Demo@2026` |

数据库模式以实际账号、密码和启用状态为准。新增或重置人员密码使用PHP密码哈希；兼容旧明文账号，登录不修改原值。人员页只显示密码状态，编辑留空保留原值，重置后旧会话失效。

样例选课截止为北京时间 **2026年11月1日17:00**。超过截止时间后，需按演示安排调整开放学期；调整日期不会重新开放已关闭学期。更多账号、课程与操作场景见[扩展测试数据说明](database/测试数据说明.md)。 该说明同时列出初始人数、各操作的数据影响和恢复方法；重复导入不会重置演示数据。

## 测试与验收

在项目根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\run_stability.ps1 -RaceRuns 1
```

脚本需要PHP、Node.js、`rg`及MySQL完整安装目录；可通过 `-PhpPath`、`-MysqlDirectory` 修改默认工具路径。演示阶段强制使用会话数据，数据库阶段自动创建独立临时MySQL实例，不使用日常数据库。`-RaceRuns 1`执行一轮最后一席竞争，省略则为10轮；不视为压力测试。结束时输出日志和 `results.json` 的位置。

日常使用只需运行上述入口。`rules.php`合并选课、任教和关课规则检查；`db_*.php`检查数据库业务，`http_*`检查网页流程，历史结果已合并到`archive/test_results.json`。

详细方法与结果见[测试计划](课程注册系统测试计划.md)和[测试报告](课程注册系统测试报告.md)。人工检查按实际执行情况记录操作条件、结果和证据，再汇总到测试报告。

### 课程要求核对

依据根目录[课程设计要求PPT](2026年软件工程课程设计要求(1).ppt)和[课程设计题目PDF](2026年软件工程课程设计题目%20.pdf)核对，提交材料对应如下：

| 要求 | 当前材料 |
| --- | --- |
| 开发计划，含人员、进度和迭代安排 | 开发计划第3—5节 |
| 需求分析、设计文档 | 需求分析包含角色、规则、用例及验收要求；设计文档包含模块、数据库、流程和权限 |
| 测试计划、测试报告 | 已列出场景、预期、执行方法及已有自动测试结果；实际人工检查按计划记录 |
| 每人工作汇报和全组总结 | 工作总结第1—4节为小组总结，第5.1—5.4节按成员归纳工作；各成员确认本人内容并补充个人体会与实际日期 |
| 成员贡献百分比 | 统一填写在工作总结第5.5节，合计100% |
| 最后一天检查程序运行 | 按README启动，在测试数据说明的前置条件下演示主要操作 |
| 软件配置管理计划与最终配置库 | PPT列为可选项；当前保留Git仓库和配置示例，不另增计划文档 |

PPT按5人一组说明，当前材料按本组约定使用成员1—成员4；小组人数以任课教师认可的安排为准。成员姓名、学号、组长和贡献比例按实际情况填写。

题目PDF与本项目的实现范围有以下区别，提交时应结合正文说明：

- PDF第4—5页使用旧式Windows桌面界面背景；PPT明确允许原生PHP等B/S方案，当前采用PHP和MySQL网页实现。
- PDF第2、5页要求读取既有课程目录；当前通过本地数据库或JSON快照模拟只读目录，未连接题目中的Ingres旧系统。
- PDF第7页包含学费计算及计费失败后的定时重发；当前保存最终课表快照并模拟发送，失败由教务员手动重试，不包含学费计算或自动重发。
- PDF第4页列出中央数据库2000并发用户、本地服务器500并发用户、目录访问延迟不超过10秒、80%的事务在2分钟内完成，以及每周全天可用且停机不超过10%的目标。现有自动测试验证业务正确性，不能作为这些性能和可用性指标达标的证明。

上述差异说明当前课程项目的范围，不替代任课教师对简化实现的验收意见。原始课件未规定必须提交截图、额外独立的部署文档或固定数量的设计图；截图位置可按现有安排保留。
