# 数据库说明

执行顺序：先在新建的开发库中运行 `schema.sql`，再按项目根目录 README 设置 `CR_DB_*` 环境变量，最后运行 `import_demo.php --demo`。导入脚本只接受空库，重复运行会拒绝。

## 表与关系

| 表 | 内容 |
| --- | --- |
| `users` | 学生、教师、教务员账号；`is_active=0` 的导入教师和占位学生不可登录。 |
| `semesters` | 选课起止时间和开放、处理中、已关闭状态。 |
| `courses`、`course_prerequisites` | 课程定义及先修课关系。 |
| `offerings`、`offering_times` | 某学期教学班、授课教师、容量、地点和每周上课时间。 |
| `teacher_claims` | 教师主动认领的来源记录；预先安排的教学班没有记录，不能自行取消。 |
| `offering_closure_results` | 每个教学班关闭前人数和开设、停开原因；再次关闭不会重算。 |
| `closure_backup_attempts` | 学生缺位时实际尝试的备选顺序及成功、满额、冲突等结果。 |
| `selection_choices` | 学生的首选和有顺序的备选；备选本身不占名额。 |
| `enrollments` | 学生的实际占座记录。仅 `status='active'` 计入教学班人数。 |
| `grades` | 对应占座记录的成绩；未录入时允许为空。教师仅能维护本人已确认、学期已关闭的教学班。 |

容量上限、时间范围和选择顺序有数据库约束；“同一学生不能选同一课程的两个教学班”“先修课合格”“学生时间不冲突”“有效人数不超过容量”等跨表规则由学生选课事务校验。教师认领在事务中锁定教师和教学班，并检查任教时间冲突。

## 样例数据

- 当前学期为 `2026—2027学年 第一学期`，含 11 个教学班。52 个有效名额与当前 PHP 演示目录一致，其中 `student01` 占 4 个，48 个为不可登录的独立占位学生。
- `student01` 的首选依次为 `SE301-01`、`DB305-01`、`CN309-01`、`AI320-01`；备选依次为已满的 `OS312-01` 和 `DSP342-01`。备选没有 `enrollments` 记录。
- 上一学期有两门历史课程及 `student01` 的“程序设计基础：良好”“数据结构：优秀”成绩，供以后验证先修课和成绩查询。
- `student02` 当前没有选课记录，但已完成两门先修课，可用于测试新提交与跨账号名额变化。`student03` 未完成先修课，可用于测试先修校验。`teacher01` 可认领当前未分配教师的教学班。

所有账号与数据仅用于开发测试。关闭选课先停开无教师或不足 3 人的教学班，再处理备选补位。

当前教师录入页接受 A、B、C、D、F、I，保存即对学生可见；历史中文样例成绩可继续查看，修改时改用字母等级。撤销成绩会将 `grade_value` 设为 `NULL`。该流程尚无单独的成绩公布阶段。

教务关闭选课须在截止后执行。事务锁定学期与教学班，先停开无教师或不足 3 人的班并释放占座，再按当前选课方案保存时间与学生 ID 处理备选补位；最终教学班状态、首选记录、占座和备选尝试原因一起提交。关闭失败则整笔回滚。
