# 课程用例补充

依据题目 PDF 的八个用例及其失败后状态不变要求补充。PPT 允许自主选择 Web 技术，因此继续使用 PHP/MySQL；外部目录和计费沿用现有模拟，不增加部署组件。

## 多窗口成绩冲突（2026-10-13）

| 场景 | 操作及预期 |
| --- | --- |
| 旧页面更正 | 两个窗口打开同一教学班；窗口一修改某学生，窗口二修改同一学生。第二次拒绝，保留第一次成绩与修改日志 |
| 旧页面撤销 | 窗口一录入新成绩，窗口二用旧页面撤销。拒绝撤销，不清空新成绩 |
| 旧页面导入 | 打开导入页面后，另一窗口修改班内成绩，再导入 CSV。整批拒绝，其他学生也不写入 |
| 旧页面确认 | 打开页面后，另一窗口修改成绩，旧页面确认提交。拒绝确认，要求核对最新成绩 |
| 不同学生分别修改 | 两窗口分别保存不同学生。均可成功，不因其他学生的变化阻止单条保存 |
| 刷新后重试 | 冲突页面显示最新成绩；核对后重新保存或确认，可以成功 |
| 原样保存与导入 | 使用当前页面保存相同成绩或导入相同值。不新增日志，不撤销已完成的确认 |
| 未录入成绩 | 撤销后显示“未录入”；全班仍有空成绩时不能确认提交 |
| 缺少页面版本 | 删除或损坏表单版本字段后提交。显示版本无效，不写数据 |

实现采用成绩内容快照和事务内当前读，无数据库结构变更。快照只用于检测编辑冲突，身份和权限仍由登录会话与数据库校验。内部 PHP 调用可省略快照，网页入口必须提供。内容恢复到原值时视为无冲突；CSV 的离线编辑历史不在检查范围内。

## 后续答辩可选的人工边界用例

下列是建议检查项，不代表本轮已全部实测。

| 用例 | 补充检查 |
| --- | --- |

## 验证与提交说明

`db_grade_conflicts.php` 在独立 MySQL 中验证事务结果；`http_db_grades.ps1` 验证真实 HTTP 表单、权限与页面提示。独立运行入口为 `powershell -NoProfile -ExecutionPolicy Bypass -File tests/run_grade_conflicts.ps1`，需要本机 PHP 和 MySQL，路径可在脚本参数中指定。不会连接现有业务库，测试日志保存在 `tmp/grade_test_*`。

本轮补丁与上述用例由 AI 辅助生成，须由小组理解、复核并按 PPT 要求标注；不要将自动检查结果写成尚未进行的人工浏览器验收。本次六份正式Word文档已随Markdown同步当前实现。

2026-10-13 实测：独立 MySQL 检查 14 项、HTTP 检查 21 项、现有选课/任教/关课规则检查 23 项全部通过；修改的 PHP 文件语法检查及 `git diff --check` 通过。HTTP 检查不等同于人工浏览器视觉验收，也不代表负载指标已达标。
